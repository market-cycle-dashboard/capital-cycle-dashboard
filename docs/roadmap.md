# 建设路线图

路线图按“先骨架、再房间、再装修”的节奏推进。每一步都应该产出可见、可复用的东西。

## Phase 0：项目骨架

目标：让项目从单页仪表盘升级为投研站点。

- [x] 建立 GitHub 仓库和 Cloudflare Pages 发布链路
- [x] 建立资本周期静态仪表盘
- [x] 明确三层结构：站点层、模块层、组件层
- [x] 新增项目蓝图和模块模板
- [ ] 将 README 升级为项目入口
- [ ] 清理或隔离历史生成文件 `shim.html`

## Phase 1：站点入口

目标：首页不再只是资本周期页面，而是整个投研系统的入口。

- [ ] 建立数据底座：数据目录、数据源登记表、更新流程
- [ ] 设计总览页结构
- [x] 增加模块状态卡片
- [x] 明确“资本周期”为第一个成熟模块
- [x] 给流动性、深度报告、数据中心、方法论预留入口
- [x] 实现模块切换（点击模块卡片切换显示内容）
- [ ] 增加最近更新区

## Phase 2：资本周期模块标准化

目标：把当前最成熟的资本周期页面整理成一个模块样板。

- [ ] 明确资本周期模块的一句话结论区
- [ ] 固化波浪图、雷达图、PB-ROE 图的说明方式
- [ ] 优化右侧详情面板
- [ ] 梳理研究池字段
- [ ] 增加资本周期方法论说明
- [ ] 将可复用组件命名并记录

## Phase 3：流动性模块

目标：用同一套模块模板建设第二个研究框架。

- [ ] 定义流动性模块的研究问题
- [ ] 明确数据来源和指标口径
- [ ] 设计核心图表
- [ ] 建立筛选和详情面板
- [ ] 形成流动性研究池或状态判断

## Phase 4：深度报告模块

目标：让站点可以承载可推广的研究内容，而不只是图表。

- [x] 定义报告类型：行业、公司、主题
- [x] 设计报告卡片
- [x] 设计报告详情页结构
- [x] 增加标签、更新时间、结论摘要
- [x] 建立报告与图表模块之间的互相引用
- [x] 实现报告筛选（类型、搜索、置信度）
- [x] 建立 reports-data.js 数据文件（6篇示例报告）
- [x] 替换示例数据为真实研究报告
- [x] 支持 Markdown 格式报告内容
- [x] 支持报告深链直达与刷新后状态恢复

## Phase 5：数据与方法论中心

目标：让站点可信、可解释、可持续维护。

- [ ] 数据流水线文档化
- [ ] 数据来源说明
- [ ] 指标口径说明
- [ ] 评分模型说明
- [ ] 数据更新时间说明
- [ ] 历史版本记录
