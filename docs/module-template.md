# 研究模块模板

每个研究模块都应按同一套结构建设。这样新增模块时，不会从零开始，也不会让导航和页面逻辑越长越乱。

## 模块基本信息

```text
模块名称：
模块状态：规划中 / 建设中 / 可用 / 成熟
所属栏目：研究框架 / 深度报告 / 数据中心 / 方法论
主要用户：自己 / 合作研究者 / 外部读者
更新频率：每日 / 每周 / 每月 / 事件驱动
```

## 1. 研究问题

这个模块必须先回答一个清晰问题。

示例：

- 资本周期：哪些行业处在资本开支退潮、供给出清、回报修复的位置？
- 流动性：当前市场定价环境是流动性扩张、收缩，还是结构分化？
- 深度报告：一个行业、公司或主题的核心矛盾是什么？

## 2. 当前结论

当前结论应放在模块第一屏，避免用户先看一堆图却不知道结论。

结构建议：

- 一句话结论
- 三个关键证据
- 当前置信度
- 最近一次更新日期

## 3. 核心图表

每个模块最多先定义 1-3 个核心图表。图表不是装饰，而是研究问题的主证据。

每个图表需要说明：

- 横轴和纵轴含义
- 数据来源
- 口径限制
- 点击或筛选后的行为
- 这个图表支持什么判断

## 4. 筛选与交互

筛选器应靠近它控制的内容，而不是统一堆在目录里。

常见筛选：

- 市场
- 行业
- 阶段
- 分数阈值
- 时间区间
- 标签

## 5. 详情面板

详情面板负责把“点一个对象后应该看到什么”标准化。

常见详情：

- 当前状态
- 核心指标
- 历史轨迹
- 诊断文字
- 相关公司或行业
- 下一步研究动作

## 6. 研究池

研究池是从图表和规则筛出来的候选对象。它不是买卖建议，而是“值得继续研究”的队列。

建议字段：

- 名称
- 所属市场或行业
- 入池原因
- 关键指标
- 风险提示
- 复核状态

## 7. 方法论

每个模块都要能解释自己为什么这么算。

至少包含：

- 指标定义
- 评分逻辑
- 数据来源
- 适用边界
- 已知缺陷

## 8. 更新记录

每次明显改动都要记录。

```text
YYYY-MM-DD
- 改动内容
- 影响范围
- 是否改变历史结论
```
