# 设计与协作原则

## 总原则

这个站点要像研究工作台，而不是营销落地页。页面应当清晰、克制、可扫描，适合反复使用。

## 信息架构

- 先给结论，再给证据。
- 先展示模块入口，再展开模块内部细节。
- 导航只负责导航，不承载筛选器和分析详情。
- 筛选器应靠近被筛选的图表或列表。
- 每个模块都要说明自己回答的问题。

## 页面布局

- 首页展示站点级结构，不塞满单一模块细节。
- 模块页第一屏展示结论、关键指标和核心图表。
- 详情面板放在图表附近，形成“看图 -> 点击 -> 解释”的路径。
- 长表格、研究池、方法论放在核心图表之后。
- 移动端允许上下堆叠，但不能丢失导航和结论。

## 视觉风格

- 保持研究终端气质：克制、稳定、信息密度适中。
- 卡片用于模块入口、列表项和指标块，不把所有页面区块都做成重装饰卡片。
- 字号层级要稳定：站点标题、模块标题、区块标题、指标文字各司其职。
- 避免无意义装饰，所有视觉元素都应帮助理解结构或数据。

## 组件原则

- 新增 UI 前先判断是否能复用现有组件。
- 组件命名要反映用途，而不是当前样式。
- 通用组件不要绑定某一个模块的业务含义。
- 一个模块成熟后，要反向沉淀成模板。

## 协作方式

每次开发前先明确：

```text
这次装修哪个房间？
这个房间解决什么问题？
改动属于站点层、模块层还是组件层？
是否影响其他模块？
完成后是否需要更新文档？
```

每次提交建议小步完成：

- 文档改动
- 页面结构改动
- 数据更新
- 样式优化
- 功能交互

不要把多类改动混在一个提交里，除非它们必须一起发布。
